# Agent Board

A local dashboard for running many Claude Code sessions in git worktrees. macOS only.

- **Repos**: add a repository, or a folder to scan for repositories and worktrees (up to 5 levels deep, rescanned every 30 s). Removing a repo hides it from later scans.
- **Sessions run in Ghostty**, in tabs of your front Ghostty window. The app has no terminal of its own: every interactive Claude Code process in a tracked repo shows up as a tile, whether you started it by hand or from the app. It finds them through `~/.claude/sessions/<pid>.json`, which also carries Claude's live status (working, your turn, waiting for a permission prompt), and maps each one to its Ghostty tab by tty. **Terminal** switches to that tab through Ghostty's AppleScript; answers and messages are typed into it the same way.
- **Worktrees**: created and removed by [`scripts/git-wt`](scripts/git-wt), also usable as `git wt` once linked into `PATH` (`ln -s $PWD/scripts/git-wt ~/.local/bin/`). A task's worktrees sit at `<repo's parent>/worktrees/<task>/<repo folder>` (root overridable per repo), so one task name can span sibling repos and `../<sibling>` paths keep working. A new branch starts from `origin/<branch>` if it exists, else the base branch (`master` → `main` → `origin/HEAD`, overridable per repo); files matched by the main checkout's `.worktreeinclude` are copied in. A task that needs no worktree of its own picks **Existing branch, no worktree** in New task instead: you only pick one of the repository's local or remote branches (the task is named by Claude's generated title, the branch until then), and Claude runs where that branch is already checked out, or else in the main checkout switched to it (refused while a Claude runs there or it has uncommitted changes; a remote-only branch gets a local tracking branch). The setup command does not run then. Each worktree lists its Claude Code conversations from `~/.claude/projects`: **New Claude** and **Continue** open a Ghostty tab running `claude` (the setup command runs first in a new worktree); **Terminal** switches to a running one.
- **Diff**: one patch per worktree against the merge-base with the base branch, including committed, staged, unstaged and untracked changes. Your index is never touched. The Diff tab lists every changed file with a few lines of context in one scrolling view; clicking a file in the tree on the left opens it alone, in full, at its first change (**← All files** goes back to where it was in the list).
- **Attention is contextual**: `pnpm claude:connect` registers the `ask_human` MCP server at user scope (`http://127.0.0.1:7420/mcp`) and allows the tool in `~/.claude/settings.json`, so every Claude session has it (running ones after a restart or `/mcp` reconnect). The app reads the call from the session transcript; the task page shows it as a decision, and your answer is typed into the Ghostty tab as the next prompt. `pnpm claude:disconnect` undoes the registration and removes the hook.
- **Priority**: open questions are ranked by `claude -p --model sonnet` using `config/priority-rubric.md`. Edit the rubric to change the ordering.
- **Two pages**: the board (`/`) shows only tiles, in this order: Decide, Needs focus (a permission prompt in the terminal), Your turn, In progress, Ended. Each tile shows its state, the task and repo, and either the decision or the one-line briefing. The browser tab's title counts the open decisions, e.g. `(2) Agent Board`. Clicking a tile opens the task page (`/s/<id>`; Esc goes back), which has two tabs, Overview and Diff. The task name is the Claude session's name: Claude's `/rename` or its generated title shows up in Agent Board, and clicking the name on the task page renames both. A running session gets `/rename` typed into its terminal (it runs even mid-turn); an ended one gets a `custom-title` line in its transcript. While Claude works, the tile and the top of Overview show its current step (the tool and what it is doing, read from the transcript) and how long the turn has run. Overview shows, top to bottom: what Claude is doing now, **Worth knowing** (only when there is something), the **Decision** (the problem, a short explanation, everything needed to decide, a button per choice saying what it does, and a reply box) or the message box, the **Status**, then Claude's latest reply in full (folded after about 16 lines; **Show all** opens it), then the facts. The briefing lags a reply by the 10 to 30 s Sonnet takes to rewrite it.
- **Claude Code's own questions** (`AskUserQuestion`) show as a decision too: each question with its options, multiple choice where allowed, and your own answer on single-choice questions. `pnpm claude:connect` installs a `PreToolUse` hook on `AskUserQuestion` that only posts the questions to Agent Board and never answers them, so the terminal menu still opens. The card clears when the transcript has the answer (the call's `tool_result`), or when the session goes idle or ends. **Send answer** drives that terminal menu with Ghostty's named keys (arrows, Enter, Tab), never digits, which a non-US keyboard layout would turn into other characters.
- **Briefing**: `claude -p --model sonnet` without tools keeps three things per task. **Status**: a headline and up to 4 progress points, refreshed after every Claude message (at most once a minute while Claude works), shown quietly below the decision. **Worth knowing**: shown in blue, and as a chip on the tile, only when the model judges that something notable came up, such as a surprising cause, a wrong assumption or a hidden risk; most tasks have none. **Decision**: taken from the `ask_human` question if one is open, restated in plain words with Claude's own details below it, or else read from Claude's last message when that asks you to decide or provide something. A decision read from the message has to stand on its own: it lists every item, proposal or file the choice refers to, and each option says what happens if you pick it, so you never need the conversation or Elaborate to decide. **Elaborate** runs a read-only `claude -p --model sonnet` (Read, Grep and Glob) in the worktree, which explains the background and what each choice would mean, citing the files it read. It runs once per decision and is stored.
- **Reply box**: Enter sends (Shift+Enter is a newline in the detail view). Text starting with `/` or `!` is typed into the session as is, so slash commands and skills work and an open question stays open; typing `/` suggests your built-in, user, project and plugin commands and skills (Tab or Enter completes). The box grows with its text. Paste or drop files into it: they are saved under `~/Library/Caches/agent-board/uploads` (kept 30 days) and sent with the message. Images go in as a paste of their own, which Claude Code turns into `[Image #N]` attachments; any other file goes in as its path for Claude to read.
- **Delete worktree** (tile menu, not for the main checkout): quits every Claude running in the worktree, closes the Ghostty terminals in it, then removes it with `git wt rm --force` and deletes its local branch, except the base branch and long-lived ones (`master`, `main`, `develop`, `trunk`, `release/*`). **Remove** in the Repos dialog does the same, but keeps the branch unless asked and refuses a worktree with changes unless Force is ticked. Both refuse when another worktree sits inside this one.
- **Second opinion**: each open question also goes to a fresh `claude -p --model opus` with your settings, plugins and MCP servers, without the session's conversation. It reads the worktree in place. Only when it wants to change code or run something that writes does it call its `scratch_copy` tool (a per-run MCP endpoint); Agent Board then makes a detached git worktree filled with APFS clones of every file (uncommitted changes, dependencies and build output included) and deletes it when the run ends. Its Edit, Write and NotebookEdit tools are blocked in the original worktree, as are `git push`, `ask_human` and every MCP tool whose name says it changes something (create, update, send, comment, execute-write and so on; see `server/mcpGuard.ts`), so it can read tickets and docs and drive a browser but not write to Jira, Confluence, mail or docs; Bash is only asked to stay out of it, and runs under your own permission rules. While it runs the decision shows a spinner, the elapsed time, its current step and a Stop button. Then it shows its chosen option, a ready-to-send reply, a confidence score and its reasoning; **Accept & send** answers the session with it, **Edit** copies it into the reply box.
- **PR to green**: when a session uses the `pr-to-green` skill, its tile and task page show the PR (linked) and the last result of `watch-pr.sh`: checks running, green, failed (or fixing while the session works on it), merged. The dot pulses while the watcher runs.

## Run

```sh
pnpm install
pnpm build              # UI → web/dist
pnpm service:install    # launchd agent: starts at login, restarts on crash
pnpm claude:connect     # ask_human MCP server for all Claude sessions
pnpm open               # Brave --app window on http://127.0.0.1:7420
```

Code changes never restart the server on their own. After pulling or editing server code, run `pnpm build` (UI) and `pnpm service:restart`; Claude sessions in Ghostty keep running either way. Re-run `pnpm service:install` after switching Node versions, since the agent pins the current `node` path.

Development: `pnpm start` runs the server in the foreground (stop the launchd agent first with `pnpm service:uninstall`), `pnpm dev` serves the UI with HMR on :5173, `pnpm check` typechecks, lints and runs the tests (`pnpm test` runs only the tests: transcript parsing, menu keystrokes, the MCP guard, and the diff and `git wt` on throwaway repos).

State lives in `~/Library/Application Support/agent-board/` (`state.db`, per-session hook/MCP config, `server.log`).

## Notes

- Needs Ghostty 1.3+ (AppleScript) and macOS Automation permission for the server to control Ghostty; no screen recording.
- Brand-new folders trigger Claude's "trust this folder" prompt once; answer it in the Ghostty tab.
- A Claude running in another terminal app or inside tmux still shows up, but Terminal and answering need it to be the foreground process of a Ghostty tab.
- Light/dark follows the system.
