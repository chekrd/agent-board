# Pitwall

A local dashboard for running many Claude Code sessions in git worktrees. macOS only.

- **Repos**: add a repository, or a folder to scan for repositories and worktrees (up to 5 levels deep, rescanned every 30 s). Removing a repo hides it from later scans.
- **Sessions run out of sight**: a Claude started from Pitwall runs in a detached tmux session (own socket `pitwall`, config `config/tmux.conf`, never your `~/.tmux.conf`), so no terminal window exists until you want one. **Terminal** (in the `⋯` menu) opens a Ghostty tab attached to it, or switches to the tab already attached; closing that tab only detaches, and Claude keeps running. The tmux sessions outlive Pitwall restarts and end when Claude quits. Every interactive Claude Code process in a tracked repo shows up on the board, whether you started it by hand or from the app. The app finds them through `~/.claude/sessions/<pid>.json`, which also carries Claude's live status (working, your turn, waiting for a permission prompt), and drives each one by its tty: tmux `paste-buffer` and `send-keys` for a hidden one, Ghostty's AppleScript for one you started by hand in a Ghostty tab. Without tmux installed, sessions open in Ghostty tabs instead.
- **Worktrees**: **New task** (N, or the top bar's button: a dialog over either view) asks for the prompt first, then the repository (its picker filters by name or path as you type; a letter on the closed picker starts the filter) and a name (a space typed in it becomes a hyphen), and ⌘↵ creates the worktree, starts Claude there with the prompt and opens its page. Worktrees are created and removed by [`scripts/git-wt`](scripts/git-wt), also usable as `git wt` once linked into `PATH` (`ln -s $PWD/scripts/git-wt ~/.local/bin/`). A task's worktrees sit at `<repo's parent>/worktrees/<task>/<repo folder>` (root overridable per repo), so one task name can span sibling repos and `../<sibling>` paths keep working. A new branch starts from `origin/<branch>` if it exists, else the base branch (`master` → `main` → `origin/HEAD`, overridable per repo); files matched by the main checkout's `.worktreeinclude` are copied in. A task that needs no worktree of its own picks **Existing branch, no worktree** in New task instead: you only pick one of the repository's local or remote branches (the task is named by Claude's generated title, the branch until then), and Claude runs where that branch is already checked out, or else in the main checkout switched to it (refused while a Claude runs there or it has uncommitted changes; a remote-only branch gets a local tracking branch). The setup command does not run then. Each worktree lists its Claude Code conversations from `~/.claude/projects`: **New Claude** and **Continue** start `claude` in a hidden tmux session (the setup command runs first in a new worktree); **Terminal** shows a running one.
- **A task across a folder of repos**: a folder that holds two or more of your repositories (say `~/code` with `web` and `api`) is listed in New task's picker above the repositories. Picked, it takes a prompt and a name only: Claude starts in an empty task folder `<folder>/worktrees/<name>`, reads the repositories' main checkouts (it is allowed to read the whole folder and told never to change a main checkout) and decides which ones the task needs. Before changing one it calls the `open_worktree` tool, which creates the worktree `<task folder>/<repo>` on the branch `<name>` with `git wt` (or returns the one that exists) and hands back that repository's setup command for Claude to run there. A Claude you start yourself in a task folder, or resume there, gets the same. The task's facts list its worktrees as they come; its Diff is one patch over all of them, each file under its repository's folder; **Clear task** names what each worktree would lose, then removes every worktree with its branch (long-lived ones kept) and the task folder; a second opinion's `scratch_copy` copies every worktree into one scratch folder. Repositories' `.claude/settings.json`, agents, commands and `.mcp.json` do not load from a task folder (Claude Code reads them from its working directory); their CLAUDE.md and skills load once Claude touches a file in the repository.
- **Diff**: one patch per worktree against the merge-base with `origin/<base branch>` (the local base branch only when origin has none), including committed, staged, unstaged and untracked changes, as of your last fetch. Your index is never touched. The Diff tab lists every changed file with a few lines of context in one scrolling view, a line too long for its side wrapped; clicking a folder in the tree on the left shows only its files, and clicking a file opens it alone, in full, at its first change (**← All files**, **All files** atop the tree or Esc goes back), and J and K step from file to file.
- **Attention is contextual**: `pnpm claude:connect` registers the `ask_human` MCP server at user scope (`http://127.0.0.1:7420/mcp`) and allows its tools (`ask_human`, `create_artifact`, `open_worktree`) in `~/.claude/settings.json`, so every Claude session has it (running ones after a restart or `/mcp` reconnect). The app reads the call from the session transcript and shows it as a card in the queue, and your answer is typed into the session's terminal as the next prompt. `pnpm claude:disconnect` undoes the registration and removes the hook.
- **Priority**: open decisions (`ask_human` calls, `AskUserQuestion` menus and questions at the end of Claude's turn) are ranked by `claude -p --model sonnet` using `config/priority-rubric.md`. The rank only orders the decisions, in the queue and on the Wall; no number is shown, and a decision's card gives the ranker's one-line reason. Edit the rubric to change the ordering.
- **Queue, Wall and task page**: the queue (`/`) shows one card at a time, in the order of attention: decisions by rank, then Needs focus (a prompt only the terminal can answer), then Your turn (Claude finished and waits for your next message), with the next two peeking out behind it. A decision's card holds what you need to answer it: the question in plain words, Claude's details (Space hides them), the options with what each does, the second opinion on the option it picked, and a reply box. The main button names what ⏎ sends; that is fixed when the card comes up, so a second opinion that arrives while you read changes it only when it had nothing to send. For 0.9 s after a card comes up or changes, the keys that answer do nothing. The top bar's meter has a segment per waiting card (past 20, a bar per kind with its count) and a **Just in** chip for one that arrived since you looked; a click on either brings that card up. With nothing waiting, the queue rests on the Wall. The **Wall** (`/wall`) has every task as a tile, in the same order, In progress and Ended after the waiting ones and the archived ones folded at the end; a tile opens its task's page; a waiting task's page leads to its card. A card's task name, and its Overview, Diff and Artifacts, open the task's page too. The **task page** (`/s/<id>`) fills the window under the top bar (a narrow window whole), with the view it was opened from kept as it was under it, and has the tabs Overview, Conversation, Diff and Artifacts, the task's `⋯` menu, and its name: the Claude session's name (Claude's `/rename` or its generated title), which a click renames in both. A running session gets `/rename` typed into its terminal (it runs even mid-turn); an ended one gets a `custom-title` line in its transcript. Esc, the back button or Back returns to the view it was opened from. Overview shows, top to bottom: for a subtask, the task it belongs to and the finding it was started from, then what Claude is doing now (the tool and what it is doing, read from the transcript, and how long the turn has run), an open decision's **In your queue** box with its whole second opinion (running with Stop, failed with Retry, or its pick, confidence and reasoning; a decision is answered on its card), the **Findings**, the **Terminal** button of a task that needs focus, or the reply box, the **Session summary**, **Worth knowing**, Claude's latest reply (always whole, under your prompt it answers, which is cut to three lines until **Show all**; what it wrote after its last tool call, with the text before a question or menu, so the progress notes between tool calls stay out; the turn before shows until the current one has such text), then the facts (the repository, the worktree's name, or None for a task in the main checkout or one whose worktree was removed, its path with `~` for your home folder, its branch and the session id; the path, branch and session id copy on a click, the path whole), the **Links** Claude gave in its messages and questions, newest first and kept after they scroll out of the transcript (each described in a few words by `claude -p --model haiku`, or by its host and path until then), a task's **Subtasks** and its **Earlier conversations**. A link to another site, there or in any reply, opens in your default browser (the server runs `open`), never in the board's window. While you type in a reply box or New task, nothing that would take the field away changes until you leave it. The browser tab's title counts the open decisions, e.g. `(2) Pitwall`, and the pill beside the name says whether the board is **Live** or **Reconnecting…** (answers sent meanwhile wait and go out once it is back). The briefing lags a reply by the 10 to 30 s Sonnet takes to rewrite it.
- **Keys** (**?** lists them): on a card, 1–9 send that option (in a menu, pick it; a digit counts by its key, so other keyboard layouts work too), ⏎ does what the main button says, → skips the card, ← brings the last one back, Space shows or hides Claude's details, W writes your own answer, E edits the second opinion's suggestion, Y elaborates, O and D open the task on Overview or Diff, and X archives a finished task. Z takes back the last send while it waits, V switches between Queue and Wall, N opens New task, and Esc closes what is open, then goes back to the queue. In the sheet, 1, 2, 3 and 4 pick the tab, and J and K step through the diff's files.
- **Agents dock**: under the queue's card, a capsule for every agent at work, with its name, its current step and how long the turn has run, and a dot for its PR or for Worth knowing; **N ended** opens the Wall. Hovering a capsule shows its card (repository and branch, the step, the PR, Worth knowing, what you answered, the summary), and a click opens the task's sheet. A send you made comes first as a capsule of its own: **Sending in N s** with **Undo**, **Sent** once it is out (or **Waiting for Pitwall** while the board cannot be reached), and then the agent at work, ringed for a moment. In a narrow window the dock scrolls sideways and shows no hover cards.
- **Artifacts**: `pnpm claude:connect` also allows the `create_artifact` tool on the same MCP server. A Claude calls it when it decides a picture explains something better than prose (a flow, a before/after, a state machine, a timeline, a comparison): a title and one self-contained HTML document of at most 100,000 characters. As with `ask_human`, the tool only acknowledges; Pitwall reads the call from the transcript and saves the HTML under the session's folder in the app's state, so it outlives the transcript window it was read from. A later artifact with the same title replaces the earlier one. The card of a task that has any links to them, and the sheet gets an **Artifacts** tab (and links in Overview) that shows them in a sandboxed frame; **Open in new tab** shows one alone. They are served with a CSP that allows only inline script, style, `data:` images and fonts and makes their origin opaque, so an artifact can neither load anything nor call Pitwall.
- **Claude Code's own questions** (`AskUserQuestion`) show as a decision too: the questions side by side, each with its options, numbered across them, multiple choice where allowed, and your own answer on single-choice questions. `pnpm claude:connect` installs a `PreToolUse` hook on `AskUserQuestion` that only posts the questions to Pitwall and never answers them, so the terminal menu still opens. The card clears when the transcript has the answer (the call's `tool_result`), or when the session goes idle or ends. **Send answer** drives that terminal menu with named keys (arrows, Enter, Tab), never digits, which a non-US keyboard layout would turn into other characters. A menu answered from the board that is still open 10 s later turns into Needs focus: Claude still shows it in the terminal.
- **Briefing**: `claude -p --model sonnet` without tools keeps three things per task. **Session summary**: a headline and up to 4 progress points, refreshed after every Claude message (at most once a minute while Claude works), shown on a Your turn or Needs focus card and in Overview. **Worth knowing**: shown in blue under the card's decision or reply box and in Overview under the Session summary, as a chip on the tile and as a dot on the dock's capsule, only when the model judges that something notable came up, such as a surprising cause, a wrong assumption or a hidden risk; most tasks have none. **Decision**: taken from the `ask_human` question if one is open, restated in plain words with Claude's own details below it, or else read from Claude's last message when that asks you to decide or provide something. A decision read from the message has to stand on its own: it lists every item, proposal or file the choice refers to, and each option says what happens if you pick it, so you never need the conversation or Elaborate to decide. **Elaborate** runs a read-only `claude -p --model sonnet` (Read, Grep and Glob) in the worktree, which explains the background and what each choice would mean, citing the files it read. It runs once per decision and is stored.
- **Reply box**: Enter sends, Shift+Enter adds a line. On a decision's card W opens it: Enter answers with what you wrote, and an option pressed while it is open takes your text along as a note. Text starting with `/` or `!` is typed into the session as is, so slash commands and skills work and an open question stays open; typing `/` suggests your built-in, user, project and plugin commands and skills (Tab or Enter completes). The box grows with its text. Paste or drop files into it: they are saved under `~/Library/Caches/pitwall/uploads` (kept 30 days) and sent with the message. Images go in as a paste of their own, which Claude Code turns into `[Image #N]` attachments; any other file goes in as its path for Claude to read.
- **Only the decision you saw**: an answer, **Dismiss**, **Elaborate** and the second opinion's **Accept suggestion**, **Stop** and **Retry** name the decision the page showed. When that is no longer the open one (answered in the terminal, replaced by a newer one, or Claude moved on), nothing is typed or changed: a toast says why, the page catches up, and your draft and attachments stay in the reply box. A message sent while the page showed no decision is held back the same way when Claude has asked something meanwhile, except a question read from the end of its turn, which comes from the very message you were replying to. `/` and `!` commands are not answers and are never held back for this. Every send waits 5 s before it goes out: the card leaves, and a toast counts down with **Undo** (or Z), which brings the card back with what the send took from the reply box. A command waits the same way but keeps its card, and Archive is not held: its toast's Undo unarchives. Closing or reloading the window sends what is waiting at once; one that never reached the board comes back on the page after it, marked **Not sent**, with what it took from the reply box. The server takes the first answer to a decision and closes the decision at once, so a second one, from another window say, is refused; a send it refused comes back right after the card you are reading, marked **Not sent**.
- **Conversation** (the task page's third tab, or 3): the task's whole conversation, oldest first, opened at your last prompt: each of your prompts, with the pictures pasted into it (a click shows one larger), and Claude's reply to it, which is what it wrote after its last tool call, as in the latest reply, so the steps between stay out, with the artifacts it made meanwhile (a click opens one in Artifacts). Commands, background-task notices and `/compact` summaries are not prompts; a turn that ended on a tool call (interrupted, or still working) shows no reply. Conversations the task had before a `/clear` come first. The transcript is read when the tab opens and again after each new reply, never in the background, and each picture only when it comes into view.
- **Open in Finder / Open in VS Code** (the `⋯` menu of a card, a tile or the task page): opens the task's worktree folder.
- **Clear task** (`⋯` menu): asks first, naming the branch, the path and what would be lost; then quits every Claude running in the task's worktree, closes the Ghostty tabs in it, removes it with `git wt rm --force`, deletes its local branch, except the base branch and long-lived ones (`master`, `main`, `develop`, `trunk`, `release/*`), and removes the task from the board with its data. A task in the repository's main checkout keeps the checkout and its branch: only its own Claude quits and its tab closes, as other Claudes may share the checkout. **Remove** in the Repos dialog does the same, but keeps the branch unless asked and refuses a worktree with changes unless Force is ticked. Both refuse when another worktree sits inside this one.
- **Findings**: when Claude's last message lists findings to act on one by one (a code review's issues, bugs or risks it found), the briefing also reads them out, each with its title, where it points and all Claude said about it. They show on the task page, and on a Your turn card in place of the latest reply, and stay until a later message lists others. Each has **Accept**, **Elaborate**, **Second look** and **Reject**, and, opened, a box for a note or your own answer (Enter or **Reply** sends it). **Reject** only marks it, keeping the note as the reason, and **Reopen** takes that back. Every other answer starts a subtask: a new Claude in the same worktree, hidden in tmux like any other until you pick **Terminal**, whose prompt holds the task, the finding and your answer and nothing of the review's conversation. Accept fixes it, Elaborate explains it and Second look checks whether it is real, the last two without changing files; each is told that others work on other findings in the same worktree at once, so it changes only what its finding needs and commits nothing unasked. A subtask is a task of its own on the board, and shows under its finding with its state. A subtask's own findings (say it reviewed its fix) get the same answers, so subtasks nest as deep as the work goes. Its card and its page name the tasks it belongs to, from the root task down (**Subtask of … › …**, a click opens that task); its page also shows above the name the finding it answers, with the answer you gave, its other subtasks and **Back to the task**. A subtask has no tile on the Wall, however deep: its root task's tile shows every subtask under it that wants you, numbered by its findings (Fix #1.2 is the fix for finding 2 of the subtask on finding 1) (a decision, a terminal prompt, a finished turn), each a click from its page, and takes that colour when they want you more than the task does, and the task's tile stands where its most urgent subtask would. The task's page lists all of its subtasks under **Subtasks**, beside the facts, a subtask's own indented under it, and among siblings those that want you first. **Clear task** on a task clears its subtasks with it, their Claudes and terminals too, also in the main checkout. A subtask has no **Clear task**, as it works in its task's worktree. Instead you settle it: **Mark solved** or **Drop** (ignored, rejected, not worth going on with), at the bottom of its **Subtask of** box or in its `⋯` menu; either takes it out of the queue like Archive, with an Undo, and when you are on its page, its task's page takes its place, and **Reopen** brings it back. A task counts the subtasks under it, at any depth, that are not settled yet (a settled subtask settles everything under it too): **2 of 4 subtasks open** beside its state on its page, on its Wall tile and over its **Subtasks** list, and once none is open it says all are solved or dropped.
- **/clear and /resume**: a task is not its conversation. `/clear` in a task's Claude starts a new conversation that takes the task over: its name, the task it belongs to, its subtasks, findings and artifacts stay, its Session summary and Worth knowing go until Claude's first reply there, an open task page stays on it, and the old conversation is listed under **Earlier conversations** with its id for `claude --resume`. Only a conversation that `/clear` started takes a task over. A `/resume` into a conversation a task ran brings that task back, and into any other starts a task of its own; either way the task it left ends and is archived.
- **Second opinion**: each open decision also goes to a fresh `claude -p --model opus` with your settings, plugins and MCP servers, without the session's conversation. It reads the worktree in place. Only when it wants to change code or run something that writes does it call its `scratch_copy` tool (a per-run MCP endpoint); Pitwall then makes a detached git worktree filled with APFS clones of every file (uncommitted changes, dependencies and build output included) and deletes it when the run ends. Its Edit, Write and NotebookEdit tools are blocked in the original worktree, as are `git push`, `ask_human` and every MCP tool whose name says it changes something (create, update, send, comment, execute-write and so on; see `server/mcpGuard.ts`), so it can read tickets and docs and drive a browser but not write to Jira, Confluence, mail or docs; Bash is only asked to stay out of it, and runs under your own permission rules. While it runs the card shows a spinner, the elapsed time, its current step and a Stop button. Then its option carries **Second opinion** with its confidence, a ready-to-send reply and its reasoning (one that picked none of the options shows apart, above them); when the card comes up with it, the main button reads **Accept suggestion**, and **Edit** (E) copies it into the reply box. For a menu it picks an answer per question, which the menu starts with, and **Use the suggestion** brings them back after you change a pick. A question at the end of a turn counts once a summary has been written from that very message, so a stale one never starts a run; a run whose decision is answered or replaced in the meantime is stopped.
- **PR to green**: when a session uses the `pr-to-green` skill, its tile, its task page, its Your turn card and its hover card in the dock show the PR (linked) and the last result of `watch-pr.sh`: checks running, green, failed (or fixing while the session works on it), merged; its capsule shows the dot. The dot pulses while the watcher runs.
- **Usage limits**: the top bar always shows how much of the plan's 5-hour and weekly limits is used (`5h 34%`, `7d 61%`; amber from 50 %, red from 80 %), with the reset time and the time of the reading on hover. A window whose reset time has passed shows 0 % until the next reading. Claude Code gives these numbers only to the status line, so your status line script (which gets Claude Code's JSON in `$input`) copies them for the board with the lines below; until it has, both show `–`.

  ```sh
  usage="$HOME/Library/Application Support/pitwall/usage.json"
  jq -ec '{at: (now * 1000 | floor), rate_limits} | select(.rate_limits)' <<<"$input" > "$usage.$$" 2>/dev/null && mv -f "$usage.$$" "$usage" || rm -f "$usage.$$"
  ```
- **Usage log**: to tell what to improve, the board records how it is used: time on each screen, the board keys pressed (and keys pressed that did nothing or that the board has no use for), the controls clicked, sends and their Undo, the requests the page made and the errors it showed. It never records what is typed, what a task or option says, or anything from the conversations. It stays on this Mac in `state.db` (table `ux_events`, kept 180 days). `pnpm ux` reports the last 30 days (`--days 7`; `--json` gives the raw events, e.g. for Claude to look for patterns).

## Run

```sh
pnpm install
pnpm build              # UI → web/dist
pnpm service:install    # launchd agent: starts at login, restarts on crash
pnpm claude:connect     # ask_human MCP server for all Claude sessions
pnpm open               # Brave --app window on http://127.0.0.1:7420
```

Pitwall was called Agent Board. `pnpm service:install` removes the old `dev.agent-board` agent and moves its state and uploads to Pitwall's folders, and `pnpm claude:connect` replaces the old MCP server, keeping its tool permissions for the sessions that still use it (`pnpm claude:disconnect` removes them). Sessions started under the old name keep working: their `ask_human` and `create_artifact` calls still count, and hidden ones stay on the old tmux socket until they end. A status line script that copies the usage limits needs the new path above.

Code changes never restart the server on their own. A UI-only change needs just `pnpm build`: open pages reload into it within about 4 s, once the server has read the new `index.html` twice, 2 s apart (a page waits while you type in it, have a dialog or menu open or a send is on its way; after 15 s the top bar offers **New version · Reload** instead). After pulling or editing server code, run `pnpm build` (UI) and `pnpm service:restart`; Claude sessions keep running either way. Re-run `pnpm service:install` after switching Node versions, since the agent pins the current `node` path.

Development: `pnpm start` runs the server in the foreground (stop the launchd agent first with `pnpm service:uninstall`), `pnpm dev` serves the UI with HMR on :5173, `pnpm check` typechecks, lints and runs the tests (`pnpm test` runs only the tests: transcript parsing, artifact storage, decisions and answering them, menu keystrokes, the MCP guard, the UI-build watcher, the diff, `git wt` and tasks across a folder of repos on throwaway repos, the Wall's tile order and the clocks, and the queue's cards, held sends, keys, pinned card and agents dock). The tests run with `HOME` set to a fresh temporary folder and `TMPDIR` to a folder inside it, so none of them can reach the live board's state and nothing they make outlasts the run.

To try UI changes away from the live board (where one key answers a real session), `pnpm mock` serves the built UI against made-up sessions on :7421 (`--scenario volume`, `--port`; `GET /mock` lists the scenarios) and answers them by the server's own rules, and `PITWALL_API=http://127.0.0.1:7421 pnpm dev` points the dev server at it; without that variable `pnpm dev` talks to the live board. `pnpm mock --legacy` answers like a server from before the `answered` record (none in the snapshot, no refusal codes, `adviceAt` ignored) and names the UI build only when a socket opens, to check a UI against one with `pnpm e2e --port <its port>`. `pnpm e2e` drives the built UI through scripted checks in headless Brave windows of their own, each worker against a mock of its own (`--workers <n>`, by default half the cores, at most 6): every check runs once at 1440×900 or narrow at 390×844, in dark, and checks colours and contrast, and takes its screenshots, in light too by switching the system's scheme while it runs. Checks that only wait out the page's timers (the 5 s hold of a send, the 0.9 s guard) run on a clock ten times faster; a few keep real time so the timers themselves stay covered. `--only <pattern>` picks checks, which is the way to work while changing something; `--matrix` runs every check in each scheme, adds 1100×900 and reduced motion; a failure leaves a screenshot in `.e2e/`. A check fails on an error in the page and on a request to any host but 127.0.0.1.

State lives in `~/Library/Application Support/pitwall/` (`state.db`, per-session hook/MCP config, `server.log`).

## Notes

- Needs tmux and Ghostty 1.3+ (AppleScript), and macOS Automation permission for the server to control Ghostty; no screen recording.
- Brand-new folders trigger Claude's "trust this folder" prompt once. Claude registers itself only after it, so a hidden session shows as waiting on its start-up prompt; answer it through **Terminal**.
- A Claude running in another terminal app or in your own tmux still shows up, but Terminal and answering need it to be a hidden session or the foreground process of a Ghostty tab.
- Light/dark follows the system until the top bar's theme button picks Light or Dark; the choice is kept in that browser, and System follows the system again.
